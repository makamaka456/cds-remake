## 2. 사용자와 일하는 규칙 (꼭)

1. **항상 한국어, 쉬운 말.** 사용자는 개발자가 아니고 영어를 못 한다. 전문 용어는 풀어 쓴다.
2. 분석·계획 요청은 코드 수정 명령이 아니다. **고치는 것은 허락받은 뒤.**
3. 원본에 없는 UI·글을 지어내지 않는다. 원본(PC 판) 글 · 모양을 그대로 따른다.
4. 사용자가 뺀 기능은 다시 넣지 않는다(§5).
5. **수정해서 APK 를 줄 때마다 보고에 꼭 넣는 3가지**:
   - ① APK 링크: `https://github.com/makamaka456/cds-remake/actions/runs/<run id>/artifacts/<artifact id>` (GitHub MCP `actions_list` → `list_workflow_run_artifacts` 로 id 를 얻는다)
   - ② 릴리즈 방법: https://github.com/makamaka456/cds-remake/releases/new → 태그 **`android-v0.9.7`** (그냥 `v0.9.7` 은 PC 릴리즈 워크플로가 돈다 — 꼭 `android-` 를 붙이라고 말한다) → Target **`ccr-f8fe62d5-4aibnh`** → zip 을 풀어 APK 를 끌어 놓고 Publish
   - ③ 붙여 넣을 릴리즈 노트(코드 블록)
6. 검수는 **가검수 + 진검수 둘 다** 해야 끝난다(§7). 단계마다 커밋·푸시.
7. 커밋 메시지 끝:
   ```
   Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
   Claude-Session: <이 방의 세션 주소>
   ```
   커밋·코드에 모델 이름을 적지 않는다.
8. 기기에서 확인 못 한 것은 확인 못 했다고 말한다. 일부만 검수했으면 그렇다고 말한다.
9. 이 방도 길어지면 한도가 빨리 닳는다(사용자가 불평했다). 큰 파일은 필요한 부분만 읽고, 기다릴 때 상태 확인을 자주 하지 않는다.

## 6. 도구 (새 컨테이너에는 없다 — 먼저 깐다)

```bash
bash CostaDelSol.Android/devtools/setup-toolchain.sh          # → $HOME/cds-tools (약 550MB, 2~3분)
export TOOLS=$HOME/cds-tools
python3 CostaDelSol.Android/devtools/check.py CostaDelSol.Android/CostaDelSol.Android.csproj   # 타입 검사, "errors: 0" 이어야
python3 CostaDelSol.Android/devtools/grow.py                   # 모자란 PC 파일 자동 링크(NOLINK 존중)
bash CostaDelSol.Android/devtools/sim/setup-sim-data.sh        # 시험기 게임 자료 → $TOOLS/game
python3 CostaDelSol.Android/devtools/sim/build.py              # 시험기 → $TOOLS/sim/sim.dll, "errors 0"
$TOOLS/dn/dotnet $TOOLS/sim/sim.dll $TOOLS/game 0 0            # MODE=… SHOTS=<폴더> 로 모드 · 스크린샷
```
시험기 모드(이번 방에서 더한 것 포함): `lag`(창 열기·끌기 시 자리잡기/그리기 횟수, `ONLY=모드,개발,설정,초상화`), `tools`, `toolinfo`, `edits`(도구에서 고친 표가 게임에 드는지), `celledit`, `overlay`(지도 덧그림 — **주의: 지금은 도시 안에서 멈춰 미니맵이 안 뜬다. 바다로 나가는 PLAN 이 이 모드에서 안 먹었다 — 고칠 거리**), 그 밖은 예전 노트 §7.

- CI(`.github/workflows/android.yml`)는 이 브랜치 푸시마다 돌고 약 3~4분. 끝나면 아티팩트 `CostaDelSol-apk`.
- `gh` CLI 는 검색에만 쓴다. CI 상태 · 아티팩트는 GitHub MCP(`mcp__github__actions_list`/`actions_get`)로 본다. 기다릴 때는 백그라운드 `sleep` 하나로 기다린다.
- 셰이더(GLSL)를 고치면 헤드리스 Chromium WebGL2 로 컴파일 확인한다(Playwright 는 깔려 있다). 셰이더 글은 ASCII 만.

## 7. 검수 (반드시 둘 다)

- **가검수(돌려서 터지는지)**: 예전 노트 §8 그대로 — 사건 전부(`MODE=qa-disc RANGE=0-275` — v1.1.65 에서 276 개였다), 도시 전부(`MODE=qa-city NOSTORY=1`, 261 곳), 전투·미니게임, 저장 왕복(`SAVETEST=1`), 긴 항해(`MODE=qa-long`). 0.9.6 기준값: 사건 276 · 도시 261 오류 0, 저장 왕복 차이는 `SavedAt · DevSeal · LastCity` 만.
- **진검수(PC 와 맞대어 조용히 빠진 것)**: 파일 대조 → 정적 훅 대조 → 포크 4개 + 안드로이드 부분 클래스 함수 대조 → WpfLite 빈 함수 중 게임이 부르는 것 → 설정 속성이 안드로이드에서 읽히는지 → 고친 빌드로 다시 돌려 이전 결과와 비교.
- 이번에 새로 들어오는 기능(새 모드 2개, 선박 등록 칸, 개발도구 인물·후원자 편집, 릴리즈 노트 창, 게임 중단 저장)은 시험기로 창을 열어 찍어 보고, 기기 확인 목록에 넣는다.

0.9.6 에 든 것: 게임 규칙·모드 전부, 동영상 APK 포함, L2/R2 책장 넘기기, 가상패드 기본(L2/R2 표시 · 기능 이름, 프리셋 2개), 모드·개발·도구 창 렉 개선(WpfLite 세터 같은 값이면 무시), 도구 창 X 닫기·ESC, 손가락 스크롤(옆으로 포함), 도구 표 칸 고치기, 모드 「대항해시대2 스타일 대화창」(`Ui/Dh2Art.cs`, `Input/ChoicePanel.cs`), 지도 새 효과 셰이더(`Game/MapRenderer.cs` — 못 받으면 기본 셰이더로), 켬/끔 칸 □/☑ 그리기(`Wpf/Controls.cs` CheckBox/RadioButton), 미니맵 투명도·표식, 고해상도 탭 기본값 끔.

알려진 문제: 앱을 지우고 다시 깔면 도구에서 고친 내용이 사라진다(커스텀 팩이 해결책이지만 이번엔 뺐다). 업데이트 때 APK 에 든 편집 파일(책 · 힌트 · 발견물 · 문화권 · 항해자)은 덮어쓴다.

## 9. 앞 방에서 배운 함정

- WpfLite(`CostaDelSol.Android/Wpf/*.cs`)의 속성 세터는 **같은 값이면 아무것도 안 해야** 한다 — 아니면 Measure 안에서 Touch → 무한 다시 배치(렉).
- 객체 초기화에서 `Content` 를 `Foreground` 보다 먼저 넣는 코드가 많다 — ContentControl 은 잴 때마다 글 속성을 맞춘다(이번에 고침).
- `pack://` 주소는 모듈 초기화에서 GenericUriParser 로 등록해 둬야 한다(안 하면 UiFont 초기화 오류).
- 시험기의 가짜 안드로이드(`devtools/sim/src/Fakes.cs`)에는 없는 API 가 있다(`Paint` 의 using/StrokeCap, `Canvas.DrawCircle` 등) — 시험기 빌드도 같이 확인.
- 파일의 BOM(첫 3바이트) 유무를 바꾸지 않는다(diff 가 지저분해진다).
- 시험기가 저장소 `exe-tables` 에 쓰지 않게 `setup-sim-data.sh` 는 복사한다.
