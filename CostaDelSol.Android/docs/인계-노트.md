## 2. 사용자와 일하는 규칙 (꼭)

1. **한국어로만.** 짧은 진행 알림·커밋 설명·보고서까지.
2. **"분석해/알아봐/계획 알려줘"는 고치라는 뜻이 아니다.** 분석·계획을 보이고 **허락을 받은 뒤** 고친다.
3. **원본을 지어내지 않는다.** 화면·문구·숫자는 PC 판 코드(EXE 주소 주석이 달려 있다)에서 가져온다.
4. **사용자가 뺀 기능은 넣지 않는다**(§9).
5. **수정을 마칠 때마다 보고에 붙인다** — 사용자가 대화를 뒤져 링크 찾는 것을 싫어한다:
   - 바뀐 것(화면에서 무엇이 달라지는지) / 직접 확인할 것
   - ① APK 바로 받기 링크(CI 실행의 아티팩트 `https://github.com/<소유자>/<저장소>/actions/runs/<run>/artifacts/<id>`)
   - ② 릴리즈 만들기: `https://github.com/makamaka456/cds-remake/releases/new` — Choose a tag → `android-vX.Y.Z` → Create new tag, **Target 은 작업 브랜치**(main 이면 옛 코드로 구워짐), 3분쯤 뒤 APK 가 붙음. 진행: `.../actions`, 목록: `.../releases`
   - ③ 릴리즈 노트(붙여 넣기용, 새 기능 / 고친 것 / 설치 주의: 디버그 키 서명이라 덮어 설치가 안 되면 옛 앱을 지우고 설치)
   - 세션은 **작업 브랜치만 푸시**할 수 있어 태그 푸시는 403 이다 → 태그·릴리즈는 사용자가 웹에서.
6. **PR 은 사용자가 말할 때만.** 커밋은 단계마다, 작업 브랜치에.
7. **검수는 가검수 + 진검수 둘 다**(§8). "오류 0"만으로 끝났다고 하지 않는다 — 실제로 미궁 64 퍼즐 연결이 통째로 빠진 채 사건 274개 검사가 오류 0 이었다.
8. 세션에는 안드로이드 SDK 가 없다. **APK 는 GitHub Actions 가 굽는다**; 로컬은 csc 타입 검사 + 헤드리스 시뮬레이터(§7). 게임 창을 화면에 띄우지 않는다(사용자는 가족·동료 눈치를 본다 — 모든 검수는 화면 없이, 결과는 PNG 로).

## 4. 올리는 순서 (제안 — 사용자 허락 후 진행)

**A. 준비**
1. `cds-remake` 클론. 작업 브랜치를 사용자에게 정해 달라고 한다(제안: `android-port`). 이 방은 **작업 브랜치에만 푸시**한다.
2. 옛 안드로이드 작업 가져오기:
   ```bash
   git remote add old https://github.com/makamaka456/cds-helper.git
   git fetch old claude/practical-allen-r0sxk9 f4c2d62      # f4c2d62 = 우리가 베낀 PC 기준(3-way 병합의 base)
   git checkout old/claude/practical-allen-r0sxk9 -- CostaDelSol.Android .github/workflows/android.yml
   ```
   (새 저장소에는 `.github/workflows/release.yml` 만 있다. 우리 `android.yml` 은 추가.)
3. 도구 준비(§7): `bash CostaDelSol.Android/devtools/setup-toolchain.sh` → `export TOOLS=$HOME/cds-tools`.

**B. 컴파일을 되살린다**
1. csproj 링크 갱신: 없어진 3개 제거(`ShipRepairDialog`·`ShipSellDialog`·`SphinxCalculatorContentViewModel`) — `원본-변경분석/링크한-파일-변화.md`. `HintListDialog` → `ListPickDialog`.
2. `python3 CostaDelSol.Android/devtools/grow.py` 로 새 PC 파일(99개 추가)을 자동 링크 → `check.py` 오류 0 까지. EF·Prism·애드온(Lua) 같은 것을 줄줄이 끌고 오면 멈추고 `NOLINK` 에 넣은 뒤 필요한 메서드만 가진 대용품을 만든다.
3. **PC 쪽 수정 14개 파일 다시 적용**(§5).
4. 대화창 대용품을 PC 공개 멤버에 맞춘다 — `원본-변경분석/대용품-API-변화.md`(예: `ChoiceDialog.Ask(..., string? cancel, ..., Window? under)`, `GameMenuRow(.., bool Grey)`, `ShipNameDialog.Ask/Settle` 새 시그니처, `NoticeDialog.Notes`, `CountDialog.NextShare`, `ConfirmDialog.Hold`).

**C. 갈라 만든 4개 화면에 원본 변경을 합친다** — `devtools/merge-forks.sh f4c2d62 v1.1.65 <출력폴더>`
- 3-way 병합(base = 우리가 베낀 옛 PC 파일, ours = 안드로이드 갈래, theirs = v1.1.65 의 `WorldMapWindow` 등). **시험 결과 충돌이 ShipMapWindow 33 · ShipMapHost 7 · CityPicView 14 · EventAnimationPopup 7군데뿐**이라 사람이 풀 만하다. 병합본은 합쳐진 줄이 늘어 컴파일해 보면 PC 전용(HWND·툴바·창 크기) 코드가 되살아난 곳이 있으니, 안드로이드 갈래에서 걷어 냈던 것을 다시 걷는다(§3의 4개 파일 설명 참고).
- 병합본을 `Map/ShipMapWindow.cs` 등에 덮고, 새 PC 이름(`WorldMapWindow`/`WorldMapHost`)에 맞춰 안드로이드 쪽 참조(`.Android.cs`, `.Overlays.cs`, `MainActivity.cs` 등)를 고친다.
- **지도 그림**: PC 가 `MapD3DRenderer` 에 큰 기능을 더했다(바다 효과·항적·도시 스프라이트·확대 모형·셰이더 `MapShaderData`…). 우리 GLES `Game/MapRenderer.cs` 는 v1.0.0 수준이다. 어디까지 옮길지 **사용자와 정한다**(§10).

**D. 새 기능 범위를 정한다** — §10 질문 목록.

**E. 자료**
- 동영상: 이제 **릴리즈 `movie-assets`**(`github.com/Kyeongrok/cds-remake/releases/download/movie-assets/`) 에 있다. PC 는 `MovieAssetDownloader` 가 "뒤에서 하나씩" 받는다. 안드로이드는 ① CI 가 받아 APK 에 넣거나(약 36MB) ② 앱이 받게. 사용자에게 묻는다. 우리 `asset/movie/` 81편(사용자가 직접 올려 준 것)은 옛 저장소 브랜치에 있다.
- CDSX·BGM: 릴리즈 `map-assets`, `bgm-assets` 가 **옛 저장소 `Kyeongrok/cds-helper`** 에 있다(새 코드의 다운로더도 그쪽을 가리킨다). 우리 CI 의 다운로드 단계는 그대로 쓴다.
- **자료 폴더**: v1.1.65 는 `UserDataFolder`(환경변수 `CDS_SAVEDIR`, 없으면 `%APPDATA%\CdsHelper`)로 세이브·설정을 정한다. 옛 `GameSave.FolderOverride` 는 없다 → 안드로이드는 앱 시작 때 **`CDS_SAVEDIR` 환경변수를 앱 폴더로 설정**하거나(가장 쉬움) `UserDataFolder` 에 안드로이드 훅을 둔다. `TableCache.FolderOverride`·`AppSettings.LastSaveFilePath = <게임폴더>/SAVEDATA.CDS`(효과음 묶음이 이 경로로 게임 폴더를 찾는다)도 확인.
- 세이브는 JSON(`GameSave`)이고 새 판은 `save/`(손 저장 10칸)·`autosave/`(10칸) 폴더를 쓴다 — 타이틀 CONTINUE/LOAD 의 목록 화면도 대용품이 필요할 수 있다.

**F. 검수 → 0.9.6** — §8. 태그는 `android-v0.9.6`.

| 파일 | 용도 |
|---|---|
| `setup-toolchain.sh [폴더]` | NuGet 패키지만으로 dotnet 런타임 + csc 컴파일러 + 안드로이드 API 참조 dll 을 꾸린다(약 550MB, 2~3분). `export TOOLS=<폴더>` |
| `check.py <csproj>` | csc 로 안드로이드 프로젝트 타입 검사(수 초). `TOOLS` 필요 |
| `grow.py` | 모자란 PC 파일을 타입 이름으로 찾아 csproj 에 링크하며 `check.py` 를 되풀이. 파일 안 `NOLINK` 에 링크하면 안 되는 파일 이름을 둔다(우리 사례 목록 포함) |
| `merge-forks.sh <옛> <새> [출력]` | 갈라 만든 4개 화면 3-way 병합 |
| `sim/build.py`, `sim/src/*.cs`, `sim/setup-sim-data.sh` | **헤드리스 시뮬레이터** — 같은 소스를 리눅스 콘솔로 컴파일해 새 판 → 도시 → 출항 → 항해 → 상륙 → 발견을 끝까지 돌리고, 모든 창을 PNG 로 찍는다 |

시뮬레이터:
```bash
export TOOLS=$HOME/cds-tools REPO=$(pwd)
python3 CostaDelSol.Android/devtools/sim/build.py              # → $TOOLS/sim/sim.dll  (errors 0 이어야)
bash CostaDelSol.Android/devtools/sim/setup-sim-data.sh        # → $TOOLS/game (CDSX 받고 표·asset 링크)
$TOOLS/dn/dotnet $TOOLS/sim/sim.dll $TOOLS/game 0 0        # 뒤의 0 0 = NEW GAME 에서 EASY·라몬. SHOTS=<폴더> 에 PNG
```
환경변수: `MODE=land|sea|gallery|walk|overlay|notes|qa-disc|qa-city|qa-long`, `PLAN="저택;도서관:열람;저택:설득;항구:함대편성,선박 편입,편성 종료,선원편성,선원모집,돌아간다,보급,출항"`(건물:차림표 줄 차례), `WPF="SupplyDialog:최대,결정"`(창별 누를 단추), `ONLY=창1,창2`, `SHOTS=`, `RANGE=0-273`, `PICK="카르낙"`, `NOSTORY=1`(도시 순회 때 이야기 잠금 풀기), `QA=1`, `SAVETEST=1`, `ROUTE="7,12,..."`(긴 항해 도시 번호), `LOADOLD=<세이브>`.
- **`build.py` 의 파일 목록과 `Program.cs`·`Fakes.cs` 가 옛 이름(`ShipMapWindow`·`ShipMapHost`)을 직접 부른다** — 이름을 맞추고, `Program.cs` 의 정적 훅·`UserDataFolder` 설정(`CDS_SAVEDIR`)도 맞춘다.
- 돌아가는 dll 을 덮어 빌드하지 않는다(프로세스가 깨짐 → `SIMOUT` 으로 출력 폴더를 번갈아). 병렬은 코어 수만큼만(16개를 띄웠다가 세그폴트).
- 원본 제작자도 화면 밖 시험 틀(`OffscreenTest`, `OffscreenHarness`)을 만들었다. 안드로이드 검수에 쓸 만한지 읽어 본다.

## 8. 검수 — 반드시 둘 다 (자세한 방법: 스킬 `cds3-android-port` → `references/qa.md`)

**가검수(돌려서 터지는지)**: 사건 전부(`MODE=qa-disc RANGE=0-273`, v1.1.65 는 사건이 늘었을 수 있음), 도시 전부 건물·차림표 줄(`MODE=qa-city NOSTORY=1`), 전투·미니게임을 끝까지(일기토·육상전 배치·해전 Set 연타·성배·탑·미궁), 저장 왕복 JSON 비교(`SAVETEST=1`), 장거리 항해(`MODE=qa-long`). 알려진 오탐: 소지금 0 이면 「금을 준다」 반복, 1480년에 없는 도시(산토메·케이프·포토시), 「앙골라」는 내륙(앙카라), 보급 없이 8일 넘게 항해 → 반란, 미니게임 포기 → 게임오버.

**진검수(PC 와 맞대어 빠진 것)**: 파일 대조 → 정적 훅 대조(`MazeGame`!) → 갈라 만든 파일 함수·본문 대조 → WpfLite 빈 함수 중 게임이 부르는 것 → "아직" 표시 → 설정 속성이 안드로이드에서 읽히는지 → 고친 빌드로 재실행해 이전 결과와 한 줄씩 비교. (`wpf-android-port/scripts/gap_audit.py` 가 후보를 뽑아 준다.)

**기기 체크리스트(사용자 15분)**: 시작 영상(화면 패드·터치로 넘김), 해전 한 판 결판, 포커·성배·탑·미궁 직접, NORMAL 새 주인공 이름 입력(이미 확인됨), 빌린 배 저장·불러오기, 「뒤로」, 소리, 4:3/16:9, 앱 백그라운드 복귀.

## 10. 사용자에게 물을 것 (허락받고 시작하기 전에)

1. 브랜치 이름(제안 `android-port`)과 PR 없이 진행해도 되는지.
2. v1.1.65 의 새 기능 중 안드로이드에 넣을 것: 지도 그림 새 기능(바다 효과·항적·도시 스프라이트·확대 모형) / 다국어(`Lang`) / 애드온·Lua / 버그 리포트·크래시 리포트(네트워크로 보내는 것) / 사용자 발견물·시나리오 / 작위·귀양·하드코어 모드 / 사용자 지정 BGM / 새 배 케치 등 — 모드 창(`ModDialog`)이 +1,200줄이라 대부분 따라온다. 기본 제안: **게임 규칙·모드는 전부 따라오게 두고(링크), 지도 그림 새 기능은 단계를 나눠**, 애드온·Lua·네트워크 전송은 빼는 쪽.
3. 동영상: APK 에 넣기(약 36MB) vs 앱이 받기.
4. 앱 버전: 0.9.6 으로 시작 → 완료 뒤 태그 `android-v0.9.6`.

## 11. 규모 감각 (정직하게)

- 처음 포팅보다는 훨씬 빠르지만 하루 이틀은 아니다. **큰 일**: 갈라 4개 화면 병합과 컴파일 복구, 지도 그림 새 기능 선택, 검수 재실행.
- 3-way 병합 시험은 텍스트 병합일 뿐이다 — 컴파일되고 화면이 맞는지는 `check.py` → 시뮬레이터 스크린샷 → 검수로만 안다.
- 단계마다 커밋·푸시하고, CI 성공을 확인한 뒤 **완료 보고 틀**(§2-5)로 APK·릴리즈 링크를 준다.
